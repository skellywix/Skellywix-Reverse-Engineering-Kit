The code is written in Rust from the C behavior. It is not a mechanical
translation, and it differs deliberately where the C code is unsafe: it
checks counts, indices and ranges that the C loader trusts.

## What is not here

- **No game data.** The levels, textures, sounds and fonts of Neverball are
  not part of this crate and are not committed to this repository. The
  `levelcheck` tool and the `shipped` test read them from a directory the user
  extracted from the original game's data package. Those files stay under the
  licenses and notices of the original release (see `LICENSE.md` and
  `doc/legal/` in the 1.6.0 source), which differ per asset (fonts, ball
  models and so on).
- **Third-party code.** The simulation crate has no dependencies. The desktop build uses the dependencies in `desktop/Cargo.lock`. The build package includes the pinned dependency sources and their notices in `dependencies.tgz`; it does not include the original game's executable or DLLs.
- `build/miniquad-i686.patch` adapts three 32-bit window attribute calls in miniquad 0.4.11 and uses the Windows `APIENTRY` calling convention for OpenGL. The compiler applies the patch to a private copy. The dependency archive retains the original source and its MIT or Apache-2.0 notices.
- **Test inputs** under `tests/` are small synthetic SOL files generated by
  `tests/support/mod.rs`; they are not game assets.

## Scope

The Windows game uses the licensed data pack from the identified original ZIP. Each asset retains its original license. Read `LICENSE.md` and `doc/legal/` in that release alongside the notices shipped with the candidate. Source or package identity alone does not establish that gameplay matches the original.
